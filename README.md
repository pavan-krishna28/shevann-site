# Shevann — Studio & Academy

A fully static React site for Shevann, built to host free on GitHub Pages. No backend, no
database, no server, no paid APIs, no secrets.

## Stack

- React 18 + Vite
- Tailwind CSS (design tokens as CSS variables, driven by the content store)
- react-router-dom with HashRouter (works on GitHub Pages without server rewrites)
- All content lives in src/data/site-content.json — components never hardcode text

## Run locally

    npm install
    npm run dev

Open the URL Vite prints (usually http://localhost:5173).

## Build for production

    npm run build
    npm run preview   # serve the built dist/ folder locally to sanity-check it

## Editing content

Two ways:

1. Edit the JSON directly — open src/data/site-content.json, change any field, save, commit,
   push. This is the permanent, source-of-truth way to change content.
2. Use the in-browser admin panel — visit /#/admin on the running site. Edits save instantly to
   that browser's localStorage (key: shevann_cms) and override the JSON at runtime, so you can
   preview changes live. To make an admin edit permanent:
   - Click Export JSON in the admin panel (downloads site-content.json)
   - Replace src/data/site-content.json in the repo with the downloaded file
   - Commit and push

   The admin panel is NOT password-protected — it's a local editing/preview tool, not a secured
   CMS. Edits made in someone else's browser at /#/admin never affect what other visitors see;
   only an exported-and-pushed JSON file changes the live site for everyone.

## Adding a page

Add an entry to the "pages" array in site-content.json:

    { "id": "pricing", "path": "/pricing", "label": "Pricing", "showInNav": true }

The route and nav link appear automatically — routing is generated by mapping over this array in
src/App.jsx. If the page needs custom layout (not just reusable sections), add a matching
component in src/pages/ and register it in the PAGE_COMPONENTS map at the top of App.jsx.

## Images

- External URLs work as-is — just paste the URL into any "image" field in the JSON.
- To use an uploaded image instead: in the admin panel's Image upload box, pick a file — it's
  converted to a base64 string you can paste into any image field. Images over ~300KB trigger a
  size warning (they'll still work, but consider compressing them first — base64 images add
  directly to the JSON file size and the page's load weight).

## Deploying to GitHub Pages

Option A — GitHub Actions (recommended, already set up):

1. Push this repo to GitHub.
2. In the repo settings, Pages, set the source to "GitHub Actions".
3. Push to main — .github/workflows/deploy.yml builds and deploys automatically.

Option B — manual:

    npm run build

Then push the contents of dist/ to a gh-pages branch (or use the gh-pages npm package), and set
that branch as the Pages source in repo settings.

Either way, no further config is needed — vite.config.js uses base: './' (relative paths), so
the build works whether it's served from the domain root or a /<repo-name>/ subpath.

## Chatbot

Fully offline — no API calls. It keyword-matches (with basic typo tolerance) against the
chatbot.knowledge array in the content store. Edit or add entries there, or through the admin
panel's raw JSON editor, to expand what it can answer.

## Project structure

    src/
      data/site-content.json      # single source of truth for all content
      context/ContentContext.jsx  # merges JSON + localStorage overlay
      components/                 # reusable, content-driven UI pieces
      pages/                      # route-level page components
      admin/AdminPanel.jsx        # local content editor, export/import JSON
      App.jsx                     # registry-driven routing
